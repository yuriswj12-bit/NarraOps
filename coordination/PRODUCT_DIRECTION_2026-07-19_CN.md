# NarraOps 产品转向（2026-07-19）

本文件是 2026-07-19 起的产品事实源。与旧的 Launch-first 讨论冲突时，以本文件为准。

## 核心定位

NarraOps 从以传统发射终端为中心的产品，转向 AI-native Narrative Discovery and Meme Operations Workspace。产品主叙事不再围绕导航栏功能介绍，而围绕“降低 Meme Dev 发现、筛选和判断叙事的成本”展开。

核心价值链：

```text
Pulse 主动发现互联网叙事
-> 解释、验证和历史样本对比
-> Send to Go
-> Go 生成固定 Schema 的发射预案
-> 用户最终确认
-> 受控后端工具执行
```

## 已确定决策

1. 当前一级产品面收束为 `Go / Pulse / Assets`。
2. `Launch` 不再作为一级导航；Launch 能力继续保留为 Go 可调用的后端工具，不再正面复制 GMGN Cooking 等成熟终端。
3. `Invite` 不再作为当前产品面，早期增长和等待列表可以后置到运营或 SaaS 流程中。
4. Pulse 是主动发现系统，不依赖用户提交。用户提交链接、文字或图片只属于 Go 的指定内容处理能力。
5. Pulse 的首要壁垒是发现和筛选，不是 UI，也不是通用大模型。
6. Pulse 的判断依据必须从历史 Meme 样本反向研究产生，不能凭主观权重直接设计评分。
7. 商业模式以 SaaS 订阅为主，核心付费用户优先验证有经验的 Meme Dev。
8. Bitget Wallet 的已发行代币叙事详情可作为短篇叙事表达参考；NarraOps 必须前移到发射前发现和判断。
9. Go 使用现成基础模型、固定工具和后端 API；模型不直接访问数据库、私钥或链上签名能力。
10. 内容域与资金执行域分离；真实链上执行必须经过用户最终确认。
11. 产品拒绝恶意操纵市场、虚假交易和掠夺流动性用途。
12. 工程语言按模块分工：TypeScript 负责产品工程层，Python 负责 Pulse 数据智能层，SQL/Supabase 负责数据库状态层，OpenAPI/JSON Schema 负责跨语言合同。

## 产品边界

### Pulse

- 主动采集互联网候选内容。
- 聚合同一故事的跨平台传播路径。
- 识别原始来源、传播阶段、新鲜度、重复度和同类 Token 饱和度。
- 用少量文字解释故事、来源、传播原因和 Meme 化理由。
- 将候选机会与历史不同 ATH 市值层级的 Meme 样本比较。

### Go

- 处理用户主动提交的内容，或接收 Pulse 传来的结构化机会。
- 生成和维护固定 Schema 的发射预案。
- 编排受控后端工具。
- 不承担全网主动发现职责。

### Launch 工具

- 保留现有参数 Schema、Launchpad 适配器、状态机、确认流程、安全门禁和审计设计。
- 不作为前端一级产品叙事。
- V1 至少保留一条 Solana 受控执行路径，但真实执行继续服从安全开关和最终确认。

## 当前优先顺序

1. 历史 Meme 市值分层研究。
2. 叙事 Schema、人工标注规范和评测集。
3. Pulse V1 数据采集与发现流水线。
4. 1-2 周影子运行与人工复核。
5. Pulse 前端重构。
6. Go 与 Pulse 联动。
7. 封闭 Beta 与 SaaS 付费验证。
